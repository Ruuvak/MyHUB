## Project
- Name: MyHUB
- Purpose: cross-platform (Windows/Linux) peripheral manager (mice, keyboards, headsets, pads), modular per device, tray icon plus settings window. First module: Logitech G502 X LIGHTSPEED over HID++ 2.0, without G HUB.
- Stack (approved 2026-10-15): Tauri 2 + Rust 1.99 (edition 2024, MSVC) + React/TypeScript/Vite UI, hidapi for HID.
- Package manager: cargo (Rust), bun 1.4.2 at `~/.bun/bin/bun` (frontend). Never npm.
- Layout: root `Cargo.toml` workspace; `crates/hidpp` (pure protocol, no I/O), `crates/core` (myhub-core), `crates/transport` (myhub-transport), `crates/devices/logitech-g502x`, `src-tauri/` (app), `src/` + `index.html` + `package.json` (UI).
- Entry points: `src-tauri/src/main.rs`, `src/main.tsx`
- Decision 2026-10-15 (revised same day, replaces host-only route a): onboard flash writes allowed only for DPI levels, default/shift DPI index and report rate, only in user profile sectors, via 0x8100 fn6/fn7/fn8 whole-sector writes. Plan and stages: `.claude/crew/plan-onboard-write.md`. Write tier allows only sectors 0x0003..0x0005 until the user's stage 5 decision. Button assignments stay read-only. Host mode (0x8100 fn1) stays as existing code; its future is open.
- Linux target for testing: Kubuntu (KDE Plasma, tray via StatusNotifierItem).

## Hardware safety rules (hard, never relax)
- Never touch firmware. No DFU (features 0x00C0..0x00C3, 0x00D0). No hidden features (type 0x40/0x60/0x68/0x70, IDs 0x18xx, 0x1Exx).
- Every HID++ request goes through a (featureId, function) allowlist; anything else throws before a byte is sent.
- Feature indexes resolved at runtime via Root 0x0000. Never hardcode.
- Own software ID (not G HUB's, not Linux kernel 0x01); ignore responses with foreign software IDs.
- Flash writes (0x8100 BeginWrite/WriteData/EndWrite) and Set* calls: never run on a device without explicit user approval in chat. First write test only on a disabled sector 0x0003..0x0005: backup, write, read back, CRC check.
- Never write ROM sectors 0x0101..0x0105. Check profile format ID == 3 (layout A) before any sector parse or write.
- Sector edits patch known fields over the raw bytes read from the device; unknown bytes stay as read.
- Tests run on fixtures only. No test may open a real device.

## Conventions
- Rust: edition 2024, default rustfmt, clippy `-D warnings`. Errors via `thiserror`; public parsed structs derive `serde::Serialize` for the UI.
- `hidpp` stays pure (no I/O, no hidapi). Device fixtures live in `crates/hidpp/tests/fixtures/` (`hidpp_read.json`, `frames.log`); integration tests in `crates/*/tests/`, shared helpers in `tests/common/mod.rs`.
